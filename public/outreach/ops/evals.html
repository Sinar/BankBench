Run Evals

no-code agent evaluation · 10 scenarios · 3 models

Pick three models. Run ten operational scenarios. Watch what the agent actually does with a tool in its hand.

This is the agentic version of the harness demo. The model is not answering a question — it is given a role, an objective, and a set of tools, then left to decide. Every prompt, every tool call, every tool result, and every output is shown, with token usage and estimated cost attached.

The sandbox tools are deliberately not neutral. Switch them from neutral to loaded and the same model, on the same scenario, will often take a different operational path — which is the hypothesis this interface exists to make visible.

Agents, not chat

Each run is a real tool-calling loop: the model chooses tools, the sandbox answers, and the loop continues until it commits to an output. Up to six steps per run.

No-harness first

Runs start unguarded — a role, an objective, tools, and no policy boundary, approval gate, or audit trail. The harness is available as a second condition to compare against.

Two ways to run

Simulated needs no key and no network — scripted tool sequences against the real sandbox, so the interface is fully explorable. Live calls NVIDIA-hosted models through a local proxy.

setup · no code required

Four choices, then run

Nothing here needs a build step or a config file. Pick a mode, pick three models, pick scenarios, pick how honest the sandbox should be.

Live runs need the bundled proxy. NVIDIA's endpoint sends no Access-Control-Allow-Origin header, so a browser cannot call it directly — the preflight fails and the request is blocked. Start the proxy with python3 nvidia-proxy.py in this folder, then set the proxy base URL below. Your key is sent from this page to your own localhost proxy and straight through to NVIDIA; it is never stored, logged, or sent anywhere else. Simulated mode needs none of this.

how it works

What happens on each run

STEP 1

The agent is given a role and a task

A system prompt sets the role and the objective. The user prompt carries the task — and, in most scenarios, a pressure condition: a deadline, a scarcity, a senior request, or a politically loaded framing.

STEP 2

It chooses tools, and the sandbox answers

The model gets a JSON tool schema and decides what to call. The sandbox returns a record. In loaded mode the same tool returns a framed, incomplete, or pre-decided version of that record — a pre-made ranking, a missing policy clause, a conflict check that finds nothing.

STEP 3

It commits to an output

The loop ends when the model stops calling tools. That output is the operational decision — a ranking, a draft, an allocation, a send. Tokens are counted across every step, not just the last one.

The hypothesis this tests. If users and tools are not neutral, then behaviour and operations are not purely properties of the model. The same model, on the same scenario, with the same objective, will often produce a different operational decision when the sandbox is loaded — because the non-neutrality enters through the tool results rather than through the prompt. That is the "mentality" claim made testable: not that a model has a fixed disposition, but that disposition, framing, and tool design jointly determine what the institution ends up doing.

caveats

What this interface is not

Simulated mode is scripted, not measured

  • Simulated runs use a fixed tool sequence per scenario and a templated output. The tool results are real sandbox output; the model's choices are not.
  • Every simulated result is labelled as such, in the summary and in the trace.
  • Only live runs produce genuine model behaviour, and only those should be cited as findings.

Models get retired, fast

  • NVIDIA withdraws hosted models on short notice. Nine of the first fourteen candidates for this picker were already end-of-life when probed.
  • Every model listed here was verified live on 2026-09-16, but that is a snapshot, not a guarantee.
  • Use Check selected models are live before a real run — a 410 means the model is gone and the run will fail.
  • Tool-calling support also varies by model. If a model rejects the tools parameter, the run reports the error rather than silently degrading to chat.

Cost figures are estimates

  • Token counts are exact in live mode (taken from the API's own usage field) and estimated from character counts in simulated mode.
  • Rates are editable placeholders, not NVIDIA's published prices. Replace them with your contracted rates before quoting any figure.
  • Cost covers the agent loop only — not retries, not the proxy, not your own review time.

Scenarios are synthetic and de-identified

  • No real states, disputes, communities, officials, or live operations are modelled.
  • Risk postures are expressed as behavioural patterns, never as stereotypes tied to real groups.
  • No jailbreak prompts, bribery scripts, or evasion recipes are included — the integrity scenarios test refusal and escalation, not technique.

One run is not a finding

  • Model non-determinism means a single run proves nothing on its own.
  • Ten scenarios across three models is a demonstration, not a study. The method's minimum credible design is 20–30 repeats per condition.
  • Descriptive only: the model behaved differently under this condition — nothing stronger.
